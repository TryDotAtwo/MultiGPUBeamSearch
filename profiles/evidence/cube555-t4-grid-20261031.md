# Cube555 2×T4 profile grid

This registry section comes from the completed private Kaggle kernel `trydotatwo/cube555-2xt4-profile-grid-20261030`, version 3. It used two Tesla T4 GPUs, a pinned Kaggle Docker image (`sha256:37c64f7dd9c54116ecd1bcc88817c5469b88387388fade02bfa8bf3fc647d461`), PyTorch 2.10.0+cu128, CUDA 12.8, LibTorch eager, and the Cube555 Transformer 0.8 + MLP 0.2 model with FP16 execution and FP32 accumulation.

Each time is one saturated full-frontier step, with both ranks reporting the same requested and effective global beam and half that many local parents. The profile batch was selected from seven correctness-passing 8,192-parent measurements per candidate on each GPU. The estimated Stream1 time is the selected per-parent inference median multiplied by the parents per rank. The slowdown is calculated from that estimate; it is not a second full-step benchmark.

## Source and archive verification

- The kernel output manifest covers 72 raw files. Every downloaded file matched its archived byte count and SHA-256. The independent rank audit passed for all seven widths; it checks both rank logs, one saturated step, the requested/effective width, and the local parent count. The notebook summary incorrectly marked rows as errors because it searched for logs in `resident-session/`; the downloaded rank logs were in each beam directory's root.
- Native source was pinned to `804efdc28d84f1d547d5f0e7fe47b2c81ec3b928`; the setup script checked out that exact revision. Reproduction of the actual wheel packaging step (CRLF-to-LF conversion) followed by `multigpubimsearch.build.source_digest` gives `c00b842d2baedd7028f2c736af7a07c297b2cad7b652dea000ed0c625a59cad1` over 133 source files. The previous comparison hashed raw Git bytes and did not mirror the wheel's newline normalization. The older 1,048,576 T4 profile uses source digest `e226ef9b2326abc5e641c7f1f9fe5d0453e170671acbba7a79ca3110269e9ed5`; it remains separate and was not relabeled.
- Model key: `cube555-ts-v1:433e0a0e051e403377f296f8102502559c28e1bdb4485204b58454561cd52345`. Transformer and MLP checkpoint SHA-256 values are stored in each content-addressed profile receipt.
- The profile records are in `profiles/records/`, referenced by `profiles/index.json`. Their evidence receipts include the per-rank log paths and hashes. Raw logs remain in the task's local `test_results/kaggle_t4_profile_grid_20261030/` archive.

## Limits

This was timing-only calibration. No solution was found. One measurement per width does not establish a global optimum, and the derived Stream1 comparison is not an end-to-end isolated baseline. The smallest beam shows materially higher downstream overhead. On reuse, the library must still perform fresh all-rank memory admission, correctness validation, and a short timing cohort; these records are exact-match starting points for this model, source, runtime, GPU topology, and beam.
