## Implemented optimization

- Opt-in compact57 layout uses 57 physical token rows instead of 64. Shape allocation, network dimensions and lane offsets share the selector; attention auxiliary scratch remains conservatively padded. Existing FMHA handles 57 queries with explicit strides. Default remains legacy layout. No model weights, precision, activation or search algorithm were changed.
- Existing FP16 TMA QKV+FF1 plus FF2 m128n128: 522,687.8 parents/s at m192/c12; after tuning, 540,787.0 at m512/c8.
- Adding compact57: 606,816.8 parents/s at m384/c12, 606,660.2 at m512/c8, and 605,832.6 at m384/c8. Selected m384/c8 as a lower-buffer near-tie. These are medians of three processes, 100 graph replays each. Throughput excludes initialization, graph construction and weight packing.
- Validation: shape regression failed before implementation with `compact57 must remove physical padding`, then passed. CUDA final-CLS test passed 64 rows. All 18 compact geometry pairs matched their padded score dumps. Eleven CSV-seeded inputs (p1-10,p1000), each with six first-sticker variants, matched original legacy GEMM+padding dumps exactly. They are not a large independent reachable-frontier corpus. Memcheck of compact57+Hopper at m128/c1 completed with zero errors.
- Synthetic benchmark input actually repeats the same pattern for Cube4 (96 is divisible by 6). Its score agreement is only a narrow sanity gate. The CSV-derived paired tests and production run provide additional evidence, but not a complete solve-quality study.
- Test launch corrections: the final-CLS regression intentionally flips its mode flags, so run it without Hopper packed-weight overrides and without inherited split-QKV. Validation baseline uses an unset GEMM policy, not unsupported `default`.
- Current LayerNorm policy sweep does not affect the main unrounded bias+LayerNorm kernel; it only touches other LN paths. Its small measured benefit does not rule out optimizing the main 17%-share kernel.
