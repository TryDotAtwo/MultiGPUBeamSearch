# H200 FF1 epilogue and Transformer Engine

## Decision

Keep the existing native FP16 profile. A new optional FF1 epilogue provides only
0.30% isolated Stream1 improvement. TE 2.19 was physically tested, including
E4M3 full-size QKV/FFN, but did not beat optimized native. No FP8 production
promotion, no default change, and no new integrated solver speedup claim.

## Environment and contracts

- Vast instance 51111383, one H200 SXM, driver 580.159.03, CUDA 12.8.93, SM90a.
- CUTLASS v3.9.2. Native base commit 27378023 plus this change.
- TE 2.19.0 compiled against existing PyTorch 2.11.0+cu128 in isolated
  `/workspace/te-venv` (`--system-site-packages`). Torch/driver not upgraded.
  Default unpinned resolver proposed Torch 2.14/CUDA13, so Torch was pinned.
- Cube4, 96 input bytes, 57 tokens, D256, 8 heads, four blocks, FF1024,
  ReLU, 24 output scores. Manifest SHA256:
  `9938b12a2d29204ddf2bfb96c6ef40ca18504fc8ca7e7d0e2e470cfc873955f8`.
- Rates below are parents/s, not 24x candidate rates. TE times GPU uint8 input
  through logits, including token prep and activation quantization, excluding
  uploads, weight loading, graph capture and final score-key conversion.
- TE adapter is benchmark-only. The reference loader and adapter keep extra
  weight representations; this is not a memory-qualified production integration.

## Native epilogue

Fixed MMA 128x128x64, cluster 1x2x1, cooperative TMA/WGMMA, existing void-C
epilogue. Hopper requires epilogue M=128 for this schedule; M=64 candidates
from the SM120 audit failed the CUTLASS compile-time contract. No schedule
change was silently made to allow them.

At M21888/K256/N1024, seven alternating triples, 300 graph replays:

| Epilogue | Median microseconds |
|---|---:|
| auto | 39.0875 |
| 128x64 | 38.0963 |
| 128x128 | 42.2659 |

Full optimized native Stream1, micro384/concurrency8, dual-LN disabled,
seven counterbalanced pairs x300 replays:

| Mode | Median parents/s |
|---|---:|
| incumbent auto | 586504.9 |
| optional 128x64 | 588276.0 |

All seven paired differences positive; median-rate ratio +0.302%.
Enable experimentally with
`BEAM_STREAM1_TRANSFORMER_HOPPER_FF1_EPILOGUE=128x64`; default remains `auto`.
Freeze configuration before capture. Small CLS GEMMs are unchanged.

Validation: full bitwise output comparison at M1/63/128/131/21888; score dumps
for competition puzzles 1-10 and 1000 match exactly. CUDA memcheck and synccheck
report zero errors for the standalone tail tests. Policy RED compile failure
then GREEN verified. Python mapping/activation contract also RED then GREEN.
These are targeted gates, not a complete repository regression suite.

## Transformer Engine

Mapped LayerNormLinear for QKV, Linear for attention output, LayerNormMLP with
ReLU for FFN. SDPA and residual addition remain outside TE modules. Tested
batches 384/768/1536/3072, seven alternating triplets, 100 graph replays each.
Weights calibrated with 20 refreshes before caching. The initial single-refresh
smoke run is retained but superseded by calibrated results.

Full four-block maximum in this sweep (batch3072):

| Backend | Parents/s |
|---|---:|
| PyTorch FP16 | 366101 |
| TE FP16 | 426137 |
| TE E4M3 delayed/calibrated graph | 458764 |

Final batch3072 rerun with distinct held-out graph inputs and final CLS
attention/MLP (QKV still full-size):

| Backend | Parents/s |
|---|---:|
| TE FP16 control | 477302 |
| TE E4M3 current scaling | 444533 |
| TE E4M3 delayed/calibrated graph | 508641 |
| optimized native optional epilogue, micro384 x8 | 588276 |

Native also splits final CLS QKV and uses different token/attention kernels;
this is a best-tested-path comparison, not a single-kernel attribution.
The `torch_fp16` control in CLS files still executes all four full blocks,
explicitly labeled in final metadata. Do not use it to claim a matched-topology
CLS speedup. The harness `flops_per_parent` is for the full reference only;
do not apply it to CLS timing or quote a CLS TFLOP/s from that field.

Delayed scaling uses calibrated scales in a raw CUDA graph, not a demonstrated
production dynamic-scale update policy. Current scaling includes per-forward
activation amax/quantization in the graph. Its loss versus TE FP16 supports the
overhead hypothesis; no new Nsight kernel attribution was collected here.

Quality is NOT qualified. On 3072 held-out varied states:

- Current scaling: max absolute score error 0.71875, RMSE 0.10479,
  minimum-score action agreement 87.92% versus PyTorch FP16.
- Delayed/calibrated: max absolute error 0.796875, RMSE 0.11058,
  minimum-score action agreement 89.42%.
- TE FP16 is numerically close, not bitexact; early full-model check had
  max error 0.03125. The adapter gate is rtol .02 / atol .08, not production
  search-quality qualification. Real CSV inputs 1-10/1000 are included in initial
  validation; held-out inputs are synthetic and are not solution replays.

## Reproduce / evidence

- `hpc/h200_te_benchmark.py --scaling current --cls-only --batches 3072 --output result.jsonl`

- Raw logs, binaries' score dumps, package plan/build logs and JSONL summaries
  are archived alongside this report. No model weights or credentials included.
- Official installation/API references:
  https://docs.nvidia.com/deeplearning/transformer-engine/installation.html
  https://docs.nvidia.com/deeplearning/transformer-engine/api/pytorch.html

An end-to-end 100M frontier pair was not run for this 0.30% component-derived
candidate. The previously measured native pipeline remains the reference.
