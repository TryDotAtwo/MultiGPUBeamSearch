# B300 preparation, 2026-09-23

Scope: native FP16 bring-up on SM103 before any FA4 or FP8 experiment. This is a local contract check, not a physical B300 measurement.

- `hpc/b300_build.sh` requires a detected B300 and CUDA 13.0+, configures `BEAM_CUDA_ARCHITECTURES=103`, and builds the production, benchmark, and CUDA-regression targets. CUTLASS 4.2+ is recommended for SM103 support; physical compilation is pending.
- `hpc/b300_fp16.sh s1` benchmarks isolated Stream1. `run` starts one or two ranks with a 256M requested beam, 32 shards/GPU by default, and explicit history budget. Hopper TMA/FP8 dispatch is off. Input, weight-manifest, and binary preflight runs before allocating the run directory.
- Local mock gate: `test_results/check_b300_launcher.sh` passed after an expected red test for missing-input acceptance. It checked one/two rank wiring, aligned capacity, and preflight. `test_results/check_b300_build.sh` passed after expected red tests for absent build script and regression target. These tests use fake binaries and do not establish CUDA compatibility or performance.
- 1xB300 Vast offer search returned no rentable instances even at 180 GB disk. A 2xB300 offer was visible around $23.183/h with 891 GB disk, but was not rented because the requested sequence starts with 1xB300. Offer and price may change.
- FA4 remains a measured candidate, not the baseline. Current model has only 57 tokens and uses a final-CLS attention path; FA4's Python/CuTe implementation is not a drop-in replacement for the current C++ CUDA-graph executor. First profile the attention share on B300, then compare exact score parity and complete Stream1 throughput before integrating it.

Physical gates still required: provision a suitable CUDA 13 image, export/check FP16 weights before hot-path tuning, compile on SM103, run CUDA regression and exact-score fixtures, sweep Stream1 microbatch/concurrency, profile the beam pipeline, then test 2-GPU scaling and actual cost. No instance was created during this preparation.
