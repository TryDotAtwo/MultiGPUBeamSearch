# Multi-node native launcher verification, 2026-11-06

Base commit `e53558fb901528de1c959d81ae1ccd2f66673e52`. Local validation used
one Windows host with PyTorch 2.8.0+cu128 and one RTX 3070 Laptop GPU.

| Execution | Result |
|---|---|
| Adapter cluster tests | `python -m pytest tests/test_cluster.py tests/test_cluster_worker.py -q` in `integrations/cayleypy_native` passed all 19 cases. Sixteen Python children observed one shared bootstrap path and independent rank directories. Fault injection exited rank 1 with code 7 and terminated the waiting peer. A stalled worker hit its wall timeout. |
| Actual torchrun supervision | Two independent `torch.distributed.run` agents with `--nnodes=2 --nproc-per-node=8` started the public module and all 16 CPU probe children on one host. Both agents exited 0. Workers recorded global ranks 0–15, worlds of 16 and local groups of 8. Global ranks 8 and 15 saw local ranks 0 and 7 on group 1. All workers received the same native NCCL ID pathname. |
| Slurm environment | A subprocess called the public CLI with a heterogeneous 8+6 simulated Slurm step, native global rank 12, node 1, local rank 4, and a single-device mask. Its child retained the step geometry and selected visible ordinal 0. Slurm itself was not installed. |
| Native rank contract | `tests/cluster_rank_tests.cpp` passed with MSVC 19.44, and with GCC 11.4 in Linux. Cases include global rank 127 on an 8-GPU node, singleton and whole-node masks, rejection above 128, node-local RAM division, and node-local headroom. |
| Physical CUDA binding | After the diagnostic change, nvcc 12.8 compiled the final `production_runner.cu` translation unit, including `--validate-stream1-scores`. The solver and diagnostic call the same device-selection helper. `cluster_cuda_device_tests` invoked it on the RTX 3070 Laptop GPU and checked the actual current CUDA device. The output was `cluster_cuda_device_tests=pass visible=1 local_rank=7 cuda_ordinal=0`. This test targeted device placement; it did not run a Cube4 score model. |
| Native executable and search | The initial cluster implementation, before the separate score-diagnostic binding change, linked `production_runner` with nvcc 12.8, NCCL 2.25.1 and CUTLASS for SM86. Build info reported 8 logical bytes, 16 storage bytes, 3 moves and 32-byte candidate metadata. The public worker launched it with a Hamming MLP, depth limit 2 and global beam 4096. It exited 0 on the RTX 3070. |

Python replay both recovered the center.

The Windows static TCP rendezvous attempt stopped in PyTorch before invoking
the worker because its TCPStore lacked libuv. The successful two-agent run used
the built-in c10d FileStore (`--rdzv-conf=store_type=file`) and
`TORCH_DISABLE_SHARE_RDZV_TCP_STORE=1`. These process runs exercised rank
assignment and supervision. Physical inter-host NCCL, network throughput,
and a solve across 16 or 128 GPUs remain unverified.
