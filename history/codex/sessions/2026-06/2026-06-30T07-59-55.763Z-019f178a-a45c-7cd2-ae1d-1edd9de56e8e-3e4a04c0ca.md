def build_fast_input_tables(
    sd: Mapping[str, torch.Tensor],
    piece_positions: torch.Tensor,
    piece_mask: torch.Tensor,
    piece_types: torch.Tensor,
) -> dict[str, torch.Tensor]:
    sd = strip_state_prefixes(sd)
    projection_weight = sd["piece_projection.weight"].detach().float()
    projection_bias = sd["piece_projection.bias"].detach().float()
    embedding_weight = sd["local_value_embedding.weight"].detach().float()
    d_model = projection_weight.shape[0]
    max_piece_size = piece_positions.shape[1]
    num_classes = embedding_weight.shape[0] // max_piece_size
    slot_rows = []
    for slot in range(max_piece_size):
        start = slot * d_model
        end = (slot + 1) * d_model
        token_start = slot * num_classes
        token_end = (slot + 1) * num_classes
        slot_rows.append(F.linear(embedding_weight[token_start:token_end], projection_weight[:, start:end]))
    piece_indices = torch.arange(piece_positions.shape[0], dtype=torch.int64)
    static = sd["piece_position_embedding.weight"].detach().float().index_select(0, piece_indices)
    static = static + sd["piece_type_embedding.weight"].detach().float().index_select(0, piece_types.long())
    static = static + projection_bias.view(1, -1)
    return {
        "fast_slot_projected": torch.stack(slot_rows, dim=0).contiguous(),
        "fast_piece_static": static.contiguous(),
        "piece_positions": piece_positions.to(torch.int16).contiguous(),
        "piece_mask": piece_mask.to(torch.uint8).contiguous(),
        "piece_types": piece_types.to(torch.uint8).contiguous(),
    }

inline ScratchAllocation alloc_stream1_scratch(
    const Stream1ModelConfig& model,
    std::uint32_t b_micro,
    std::uint32_t lane_count) {
    ScratchAllocation scratch;
    try {
        const std::uint64_t rows = stream1_inference_rows(b_micro, model) * lane_count;
        if (model.backend == STREAM1_BACKEND_MLP) {
            BEAM_CUDA_CHECK(cudaMalloc(&scratch.hidden1, rows * model.hidden1 * sizeof(half)));
            BEAM_CUDA_CHECK(cudaMalloc(&scratch.hidden2, rows * model.hidden2 * sizeof(half)));
            BEAM_CUDA_CHECK(cudaMalloc(&scratch.residual, rows * model.hidden2 * sizeof(half)));
            BEAM_CUDA_CHECK(cudaMalloc(&scratch.output, rows * model.output_dim * sizeof(half)));
            return scratch;
        }
        if (model.backend == STREAM1_BACKEND_PIECE_TRANSFORMER) {
            const std::uint64_t token_values = rows * model.seq_len * model.d_model;
            const std::uint64_t qkv_values = rows * model.seq_len * 3ULL * model.d_model;
            const std::uint64_t attention_values = rows * model.nhead * model.seq_len * model.seq_len;
            const std::uint64_t context_values = rows * model.seq_len * model.d_model;
            const std::uint64_t ff_values = rows * model.seq_len * model.ff_dim;
            const std::uint64_t logits_values = rows * model.output_dim;
            // Future attention kernels can overwrite this float score buffer with softmax probabilities in place.
            BEAM_CUDA_CHECK(cudaMalloc(&scratch.transformer_tokens, token_values * sizeof(half)));
            BEAM_CUDA_CHECK(cudaMalloc(&scratch.transformer_qkv, qkv_values * sizeof(half)));
            BEAM_CUDA_CHECK(cudaMalloc(&scratch.transformer_attention_scores_probs, attention_values * sizeof(float)));
            BEAM_CUDA_CHECK(cudaMalloc(&scratch.transformer_attention_context, context_values * sizeof(half)));
            BEAM_CUDA_CHECK(cudaMalloc(&scratch.transformer_ff_hidden, ff_values * sizeof(half)));
            BEAM_CUDA_CHECK(cudaMalloc(&scratch.transformer_logits, logits_values * sizeof(half)));
            return scratch;
        }
        throw std::runtime_error("unsupported Stream1 backend in scratch allocation");
    } catch (...) {
        free_stream1_scratch(scratch);
        throw;
    }
}

inline TransformerNetworkViewHolder transformer_network_view(
    const DeviceTransformerWeights& weights,
    const Stream1ModelConfig& model) {

    }

            b.ln1_gamma,

            b.attn_qkv_bias,
            b.attn_out_weight,
            b.attn_out_bias,
            b.ln2_gamma,
            b.ln2_beta,
            b.ff1_weight,
            b.ff1_bias,
            b.ff2_weight,
            b.ff2_bias};
    }
    holder.view = Stream1TransformerNetworkView{
        weights.fast_slot_projected,
        weights.fast_piece_static,
        weights.cls_token,
        weights.input_ln_gamma,
        weights.input_ln_beta,
        weights.output_ln_gamma,
        weights.output_ln_beta,
        holder.blocks.data(),
        weights.output_weight,
        weights.output_bias,
        weights.piece_positions,
        weights.piece_mask,
        weights.piece_types,
        transformer_dims(model)};
    return holder;

Read-only architecture memo for `D:\100XH100\.worktrees\stream1-piece-transformer`.

**Context**
The current `piece_transformer` is correct and production-wired, but it is not naturally shaped for this beam runtime. One parent row becomes `51` token rows, then each of 4 layers runs LayerNorm, QKV GEMM, custom `seq_len=51` attention, output projection, FFN GEMMs, residual kernels, final CLS norm, and output GEMM. The loader/exporter also currently hard-require the exact p900 shape: `state_len=120`, `num_pieces=50`, `seq_len=51`, `d_model=256`, `nhead=8`, `layers=4`, `ff_dim=1024`, `output_dim=24`.

**1. Current Piece Transformer With Optimized CUDA**
Runtime friendliness: medium-low. Removing global attention scratch and fusing attention softmax/value accumulation would help, but the model still pays for token expansion, QKV, attention, and many small per-token kernels. The FFN is also large: `51 * 1024` hidden activations per parent per layer.

Exporter/runtime changes: low-to-medium if keeping dimensions fixed. Optimize `cuda/stream1.cu` only; no trainer/export shape change.

Quality risk: lowest. Same trained model and behavior, only numerical drift.

Assessment: useful near-term cleanup, not the best long-term inference architecture.

**2. Smaller Piece Transformer Variants**
Runtime friendliness: medium. Reducing layers from `4 -> 2`, `d_model 256 -> 128/192`, and `ff_dim 1024 -> 512/768` cuts GEMM and scratch cost directly. But attention still creates awkward small/medium kernels over 51 tokens, and runtime remains more complex than MLP.

Exporter/runtime changes: medium. Current exporter and loader reject non-4-layer and non-1024-FF models, and `tools/stream1_weight_io.hpp` hard-codes transformer constants. This would require relaxing shape validation, dynamic byte sizing, scratch sizing, and tests.

Quality risk: medium. Smaller transformers may retain piece inductive bias, but quality loss is plausible unless trained/distilled carefully.

Assessment: a reasonable ablation family, but still carries transformer runtime tax.

**3. MLP-Mixer / Piece-Mixer Without QKV Attention**
Runtime friendliness: high. Keep 50 piece tokens, but replace QKV attention with deterministic token mixing and channel MLPs. Good shapes would be:
`piece embedding -> channel projection -> repeated [token-mix over 50 tokens, channel-mix over d] -> CLS/mean pool -> 24 outputs`.
Token mixing can be implemented as dense GEMMs or fixed small matrices over token dimension, with no attention score/probability scratch and no softmax.

Exporter/runtime changes: medium-to-high. New backend/manifest, new exporter, new runtime kernels. But the runtime is much simpler than attention: mostly GEMM plus bias/activation/residual. It should reuse much of the existing CUTLASS path philosophy.

Quality risk: medium. It keeps piece locality and cross-piece communication, but loses content-dependent attention. For this domain, that may be acceptable because `state_len=120` is fixed and piece layout is fixed; the network may not need dynamic attention as much as a language model would.

Assessment: best “new architecture” candidate if we want a model that is still piece-aware but much more GPU-friendly.

**4. Distill Transformer Into Residual MLP For Stream1**
Runtime friendliness: highest. The current MLP path is the runtime’s natural shape: folded sparse input, large TensorCore GEMMs, residual MLP blocks, direct score ring output. It avoids token scratch, attention, and `51x` row amplification. It also already supports `output_dim=24` and `output_dim=1`.

Exporter/runtime changes: low if using existing MLP manifest formats. Training pipeline changes only: use transformer logits/rank targets plus original labels/search outcomes to train an inference MLP.

Quality risk: medium-high. The MLP may lose piece-structured generalization, but distillation can target exactly what Stream1 needs: rank ordering of 24 moves under beam search, not faithful absolute Q values.

Assessment: best throughput-first direction and lowest engineering friction.

**5. Two-Stage MLP Fast Pass + Transformer Reranker**
Runtime friendliness: mixed. If transformer reranks only a very thin tail, this can recover quality while keeping average cost bounded. But Stream1 currently scores all candidates before Stream2/3/4 thresholding. A reranker implies a new candidate staging path: fast MLP scores, local top-k/thin-tail selection, transformer scores only selected parent/move candidates, then merge/write final score keys.

Exporter/runtime changes: high. This is not just a model backend; it changes Stream1 scheduling and score production semantics. It also risks interfering with downstream assumptions unless carefully designed.

Quality risk: low-to-medium if implemented correctly. It can preserve transformer guidance for borderline candidates.

Assessment: attractive later, but too invasive as the next training target.

**Recommendation**
Train a distilled residual MLP next, using the current p900 transformer as teacher. Target the existing Stream1 MLP runtime first, preferably `output_dim=24` for parent-row scoring unless experiments show the `output_dim=1` child-row model ranks better after distillation. Optimize the training objective for move ranking/top-k retention under beam-search selection, not pure MSE on Q values.

In parallel, keep a smaller “piece-mixer” experiment as the next architecture branch after the distilled MLP baseline. It is the most promising structural replacement for attention because it preserves piece layout while matching the runtime’s preferred GEMM-heavy execution. I would not spend the next training cycle on smaller QKV transformers unless the goal is specifically to salvage the current transformer code path; the runtime shape remains inferior even after CUDA optimization.
