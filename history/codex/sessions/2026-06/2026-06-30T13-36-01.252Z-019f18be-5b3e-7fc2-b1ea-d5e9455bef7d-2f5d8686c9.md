   - Expected benefit: small-to-moderate instruction reduction across build input, LN, SiLU, residual.
   - Risk: low if generic path remains and tests cover both dtype dispatches.

4. **Optimize `build_input` state loads**
   - File/function: `cuda/stream1.cu`, `stream1_transformer_build_input_kernel`

   - Expected benefit: moderate; `build_input` is `8.9%` GPU time with only `197` launches.
   - Risk: medium-low; must preserve `State128` logical byte rules and exact piece table indexing.

5. **Use CUTLASS epilogues where already equivalent**
   - File/function: `cuda/stream1.cu`, `stream1_transformer_residual_bias_add_kernel`; `stream1_cutlass_linear_cuda`
   - Current issue: attention out and FF2 GEMMs write branch output, then separate residual+bias kernels add into `scratch.tokens`; residual kernels are `3.7%` GPU time and `1576` launches.
   - Change: add a specialized CUTLASS linear wrapper for `D = alpha * A*B + residual + bias` for `attn_out` and `ff2`, leaving FF1/MLP path unchanged.
   - Expected benefit: saves two launches per layer and one full read/write pass over token rows.
   - Risk: medium; CUTLASS epilogue customization is more invasive than kernel cleanup, but architecture and MLP path stay unchanged.
